# 0009. 副对话是盖在主对话上的一层，分叉复用论文前缀

**状态**：已采纳
**日期**：2026-09

## 背景

主时间线里追问一个术语，新回答接在末尾，用户要翻很久才能回到原来的段落。
需要针对主对话里某一段做短问（「针对选段提问」），问完回到原处。

论文全文已经冻在 `[0][1][2]`。副对话必须复用这份前缀，不能另开一套 system。

## 决策

主对话始终是底。副对话是同一 iframe 里的 **overlay**（只做透明度淡入），
不是标签页、不是第二条主时间线。

- 入口：助手消息里划词出现「针对选段提问」，或 hover 操作条里的同一动作。划词条必须用不透明底，hover 不得换成半透明 fill。
- 打开时主对话不滚动、不追加消息；`← 正文` / Esc 回到离开时的位置。
- 副对话不写回主时间线。主消息上留标记，点开再进同一层 overlay。
- 不允许副对话再开副对话。
- 每条副对话在创建时 **快照** 当时的主历史；之后主对话继续问，旧副对话不跟。

请求形状：

```
[0][1][2]                 与主对话相同的论文前缀
[3..k] 分叉时的主历史
副对话已完成轮次
当前轮：directives（含 aside 短问说明）+ 首轮 <aside-quote> + question
```

每条副对话自己的 `PrefixLedger`，创建时 `commit(prefix + forkTurns)`。
`beginConversation`（新对话）清掉该附件下全部副对话。

## 理由

**为什么是 overlay 不是 Tab。** Tab 会让人觉得离开了主对话。盖一层、顶栏始终
有「正文」，才是「短暂跳出再弹回」。

**为什么快照主历史而不是永远跟最新主对话。** 主对话再问一轮会改前缀，旧副对话
自己的缓存会被打穿。新问题如果需要更新后的主上下文，从主消息再开一条「针对选段提问」。

**为什么引用只在首轮后缀。** 和划词一样，易变内容不能进冻结前缀。进了历史之后
后续轮不必再贴一遍。

### 被放弃的选项

- 把追问接在主时间线末尾：正是要修的问题。
- 顶栏会话列表：感觉在换会话。
- 副对话套副对话：300px 侧栏会迷路。
- 结束时强制把结论贴回主对话：主记录又变长。
- 把副对话指令写进 system / 论文块：论文 Cache 全废。

## 代价

- 旧副对话看不到分叉之后的主对话。
- overlay 期间 PDF「解释选区」会先关掉 overlay 再打进主对话。
- 内存会话：关标签 / 新对话会丢掉副对话。

## 证据

- `src/llm/prefixBuilder.test.ts`：aside 请求的 `[0..k]` 等于 `prefix + fork`；
  主对话下一轮仍能通过自己的 ledger；`<aside-quote>` 只出现在副对话当前轮。
- 面板：主对话条数在打开/关闭 overlay 前后不变；Esc 与 `← 正文` 关闭 overlay。
